# 16-bit MIPS-Inspired Processor in VHDL

A custom **16-bit pipelined processor inspired by the MIPS architecture**, implemented in **VHDL** and developed with **Intel Quartus Prime Lite 20.1** for a **Cyclone IV E EP4CE10E22C6 FPGA**.

> This is an educational MIPS-inspired architecture with a custom 16-bit instruction set. It is **not binary-compatible with the standard MIPS ISA**.

## Highlights

- 16-bit datapath and 16-bit instructions
- 5-bit opcode field
- Pipelined datapath with four inter-stage pipeline registers
- 8 × 16-bit general-purpose register file
- Register 0 hardwired to zero on reads
- 16-bit ALU
- 256 × 16-bit instruction ROM
- 32 × 16-bit data RAM
- Sign extension from 8 to 16 bits
- Branch and jump control
- Memory-mapped input/output
- Five prioritized external interrupts
- Quartus Vector Waveform test files included

## Processor overview

The top-level entity is `uP`.

Its main external interface is:

- `Entrada[15:0]`: 16-bit external input
- `Salida[15:0]`: 16-bit external output
- `clk`: system clock
- `INT0 ... INT4`: external interrupt requests
- `contadorP[7:0]`: program-counter observation output
- `ALU11[10:0]`, `ALU22[10:0]`: internal datapath observation outputs

The project is built around a pipelined datapath:

```text
             ┌───────────────────┐
             │ Program Counter   │
             └─────────┬─────────┘
                       │
                       ▼
             ┌───────────────────┐
             │ Instruction ROM   │  IMemory
             └─────────┬─────────┘
                       │
                 ┌─────▼─────┐
                 │ IF / ID   │  reg1
                 └─────┬─────┘
                       │
          ┌────────────┼─────────────┐
          │            │             │
          ▼            ▼             ▼
    Control Unit    Register      Sign
     Control_U        File       Extension
                       │
                 ┌─────▼─────┐
                 │ ID / EX   │  reg2
                 └─────┬─────┘
                       │
                       ▼
                 ┌───────────┐
                 │    ALU    │
                 └─────┬─────┘
                       │
                 ┌─────▼─────┐
                 │ EX / MEM  │  reg3
                 └─────┬─────┘
                       │
                       ▼
             ┌───────────────────┐
             │ Data memory / I/O │  memoria
             └─────────┬─────────┘
                       │
                 ┌─────▼─────┐
                 │ MEM / WB  │  reg4
                 └─────┬─────┘
                       │
                       ▼
                 Register File
                  write-back
```

## Pipeline

The source contains four explicit pipeline registers:

| Register | Role |
|---|---|
| `reg1` | Instruction fetch → decode |
| `reg2` | Decode → execute |
| `reg3` | Execute → memory |
| `reg4` | Memory → write-back |

This gives the design the structure of a classic **five-stage pipeline**:

1. Instruction Fetch
2. Instruction Decode / Register Read
3. Execute
4. Memory
5. Write Back

The current design does not contain an explicit forwarding or stall unit. The example instruction ROM includes NOP padding, which can be used to separate dependent operations during testing.

## Instruction encoding

The control unit decodes:

```text
instruction[15:11] = opcode
```

so the architecture provides a **5-bit opcode space**.

The remaining instruction fields are interpreted differently depending on the instruction class. The datapath supports register operands, an 8-bit immediate path with sign extension, destination-register selection, branch targets and jump targets.

| `00110` | ANDI |
| `00111` | OR |
| `01000` | ORI |
| `01001` | XOR |
| `01010` | NOT |

The exact behavior is determined by the 13-bit control word generated by the control unit.

## ALU

The ALU receives two 16-bit operands and a 3-bit operation code.

Implemented ALU operations include:

| ALU code | Operation |
|---|---|
| `000` | Immediate/data pass path |
| `001` | NOT |
| `010` | ADD |
| `011` | SUB |
| `100` | AND |
| `101` | OR |
| `110` | XOR |

The ALU also generates:

- `Zero`: asserted when the result is zero
- `CMP`: driven from the result MSB and used by branch logic as a signed-condition indicator

## Register file

`regfile.vhd` implements:

- **8 registers**
- **16 bits per register**
- two asynchronous read ports
- one synchronous write port
- 3-bit register addresses
- register 0 reads as constant zero

The register file writes on the **falling edge** of the clock, while the main pipeline registers use the rising edge.

## Instruction memory

`IMemory.vhd` implements a:

```text
256 × 16-bit ROM
```

addressed by the 8-bit program counter.

The ROM currently contains test programs and interrupt-service code directly initialized in VHDL.

## Data memory and memory-mapped I/O

The `memoria` subsystem combines RAM and external I/O behind one address space.

The internal RAM is:

```text
32 × 16-bit
```

The address decoder reserves two addresses for external devices:

| 5-bit address | Function |
|---|---|
| `11110` | External input |
| `11111` | External output |
| all others | Data RAM |

This allows software running on the processor to access FPGA I/O using the same datapath used for memory operations.

## Interrupt system

The processor implements five external interrupt inputs with fixed priority:

```text
INT0 > INT1 > INT2 > INT3 > INT4
```

When an interrupt is detected, `InterruptHandler.vhd` redirects the program counter to a fixed interrupt-service address:

| Interrupt | ISR address |
|---|---:|
| INT0 | 175 |
| INT1 | 193 |
| INT2 | 210 |
| INT3 | 225 |
| INT4 | 240 |

The interrupt multiplexer overrides the normal next-PC path while an interrupt request is active.

## Branch and jump logic

The next program counter can be selected from:

- sequential execution (`PC + 1`)
- a branch target
- a jump target
- an interrupt vector

Branch decisions use the ALU `Zero` and `CMP` flags together with the branch-control field propagated through the pipeline.

The Quartus project targets:

```text
Family : Cyclone IV E
Device : EP4CE10E22C6
Tool   : Intel Quartus Prime Lite 20.1
```

The Quartus project files are:

- `uP.qpf`
- `uP.qsf`

## Simulation

The repository includes Quartus Vector Waveform files:

- `Waveform.vwf`
- `Waveform1.vwf`
- `Waveform2.vwf`

Generated simulator outputs are intentionally excluded from Git through `.gitignore`.

## Building the project

1. Install Intel Quartus Prime Lite.
2. Clone this repository.
3. Open `uP.qpf`.
4. Confirm that `uP` is the top-level entity.
5. Run **Analysis & Synthesis** or **Compile Design**.
6. Use the included `.vwf` files for waveform-based verification.
